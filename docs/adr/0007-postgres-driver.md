# ADR-0007: Postgres driver

Status: accepted, 2026-11-13

The platform talks to Postgres through psycopg 3 (`psycopg[binary]>=3.3`), with plain SQL and no ORM. The journal in `flow` is the only user in this slice: four tables, a dozen statements, each written out where it is used. psycopg 3 has a native asyncio interface, which the runner needs because model calls are async, and a sync interface with the same API for scripts and reports; it is typed, adapts `jsonb`, `numeric` to `Decimal` and timestamps without extra code, and is the maintained successor of the driver most Postgres documentation assumes. Cost: the licence is LGPL-3.0-only, which allows use as an unmodified library in a project under any licence but is a stricter term than the rest of the dependency tree (MIT, BSD, Apache), and the `binary` extra ships its own libpq, which is the documented choice for development and is replaced by the system libpq build for a production image. Alternatives considered: asyncpg (Apache-2.0, faster on large result sets, async only, its own parameter style and no sync path; speed is not the constraint when each step is dominated by a model call); SQLAlchemy on top of either driver (a query builder and session model for a dozen fixed statements, and a second place where a transaction boundary could hide); psycopg 2 (no asyncio).
